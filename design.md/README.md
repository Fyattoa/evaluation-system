# 评估体系设计文档

## 设计目标
- **无需标准答案**：以原文档为黄金标准，避免人工标注成本
- **双流评估**：独立评估召回质量和生成质量，快速定位瓶颈
- **支持通用/父子分块模式**，适配不同知识库构建策略

## 四维度定义与计算公式

每个维度均采用 1-10 分制，分数越高表示质量越好。

### 相关性 (relevance)
- **解决的问题**：检索或生成的内容是否跑题
- **公式**：无关内容比例 = 无关内容字符数 / 回答总字符数
- **评分区间**：9-10分（<5%无关） → 1分（>95%无关）

### 完整性 (completeness)
- **解决的问题**：信息是否齐全，有没有遗漏关键点
- **公式**：覆盖比例 = 已包含的关键信息点数量 / 答案中关键信息点总数量
- **评分区间**：10分（>90%覆盖） → 1分（0-10%覆盖）

### 准确性 (accuracy)
- **解决的问题**：事实、数字、术语是否正确
- **公式**：错误比例 = 错误事实数 / 事实声明总数
- **评分区间**：9-10分（错误比例<15%） → 1分（>95%错误）

### 忠实度 (faithfulness)
- **解决的问题**：模型是否编造了文档中没有的内容
- **公式**：编造/删减比例 = （编造字符数 + 删减关键信息字符数） / 总字符数
- **评分区间**：9-10分（编造比例<2%） → 1分（>95%编造）

## 两级完整性设计

为了解决“知识被切碎”的问题，引入两级完整性：

- **片段级完整性**：单个 chunk 中包含的关键信息点比例。低分表示该 chunk 信息碎片化，单独一个片段提供的信息很少。
- **问题级完整性**：合并所有召回 chunk 后，覆盖全部答案关键点的比例。

**诊断逻辑**：
| 片段级完整性 | 问题级完整性 | 诊断结论 | 优化方向 |
|------------|------------|----------|----------|
| 低 | 高 | 信息被切碎到多个片段中 | 调整分块策略（增大 chunk size 或使用语义分块） |
| 低 | 低 | 检索本身遗漏了关键信息 | 优化检索模型（降低阈值、换 Embedding、增加 Rerank） |

**示例**：某个问题应有 5 个关键点。召回 3 个 chunk，分别覆盖了 1、2、1 个点，则片段级完整性 = (1+2+1)/3/5 ≈ 27% → 3 分；合并后覆盖 4 个点 → 问题级完整性 = 80% → 8 分。结论：信息被切碎，需调整分块。

## 加权得分计算

### 召回评估加权分（总分 10）
- 权重：相关性 15%，问题级完整性 35%，准确性 25%，忠实度 25%
- 理由：业务中最重要的是答案**完整**（问题级完整性 35%），其次是**准确**和**忠实**（各 25%），相关性稍低（15%）因为少量无关内容可容忍。

### 生成答案评估
- 四项均等权重（各 25%），因为相关性、完整性、准确性、忠实度对最终回答同等重要。

## 历史信息模式

在评估 prompt 中注入两部分内容：
- **历史优化信息**：过去实验的配置与得分（例如：`配置A（TopK=5, 阈值0.5）→ 7.2分；配置B（TopK=7, 阈值0.5）→ 8.5分`）
- **当前参数**：当前知识库配置（如分块模式、检索方式、TopK、阈值等）

**要求 LLM**：
1. 判断当前配置是否历史最优；
2. 如果不是，给出具体优化建议（如调整阈值、更换 Embedding 模型），并说明预期效果。
