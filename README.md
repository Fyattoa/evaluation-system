# RAG 评估体系

自建 RAG 评估系统，无需标准答案，通过四维量化指标评估知识库召回质量和 LLM 生成答案质量。

## 核心特性

- 无需标准答案：以原文档为黄金标准
- 四维量化评分：相关性、完整性、准确性、忠实度
- 双流评估：独立评估召回片段和生成答案，快速定位瓶颈
- 两级完整性诊断：区分“切片过碎”与“检索遗漏”
- 支持通用/父子分块模式，可带历史信息自动生成优化建议
- 提供可直接导入 Dify 的 Prompt 模板
- 配套自动化脚本（调用 Dify API + 评估模型）
- 可与 RAGAS 交叉验证

## 评估指标

| 指标 | 环节 | 低分含义 |
|------|------|----------|
| 相关性 | 检索 | 召回内容混入无关信息 |
| 完整性（片段级） | 检索 | 单个 chunk 信息量不足 |
| 完整性（问题级） | 检索 | 多 chunk 合并后仍缺信息 |
| 准确性 | 生成 | 事实错误 |
| 忠实度 | 生成 | 模型幻觉 |

## 目录结构

```
evaluation-system/
├── README.md                 # 本文件
├── design.md                 # 设计文档（维度定义、公式、权重）
├── prompts/                  # 评估 Prompt 模板（可导入 Dify）
├── scripts/                  # 自动化脚本
└── results/                  # 评估结果示例
    ├── knowledge_build/      # 知识库构建效果
    ├── retrieval_node/       # 检索节点召回效果
    └── llm_answer/           # LLM 生成答案效果
```

## 快速开始

1. 将 `prompts/` 中的模板导入 Dify 工作流。
2. 配置评估 LLM（如 GLM-5.1）和 Dify API。
3. 运行 `scripts/auto_evaluate.py` 或手动调用工作流。
4. 获得 JSON 格式评估报告。

## 实际成果

基于本体系调优，将 RAG 检索质量从 **7.3 分提升至 8.7 分**（满分 10），准确性和忠实度达到满分。

## 与 RAGAS 对比

| 对比项 | 本体系 | RAGAS |
|--------|--------|-------|
| 是否需要标准答案 | 否（以原文档为准） | 部分指标需要 |
| 评估粒度 | 片段级 + 问题级 | 仅问题级 |
| 是否能定位“切片过碎” | 是（两级完整性） | 否 |
| 历史信息优化建议 | 支持 | 否 |
| 输出 JSON | 自定义详细 | 固定聚合指标 |

## 注意事项

- Prompt 中的 JSON 格式请按实际 Dify 输出调整。
- 脚本中的 API Key 务必使用环境变量，不要硬编码。
